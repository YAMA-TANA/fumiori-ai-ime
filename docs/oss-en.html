Open source

Fumiori-specific code is published under the Apache License 2.0. Source code, build scripts, GitHub Actions workflows and modifications to Mozc are publicly reviewable.

Third-party components such as Mozc, Ruri, ONNX Runtime and Qt retain their respective upstream licenses. They are not relicensed merely because they are distributed as part of Fumiori AI IME.

Privacy policy

IME input, conversion candidates, surrounding context, dictionary data, document-domain settings, custom instructions and AI inference are processed on the user's Windows PC.

  • Typed text and surrounding context are not sent to an external AI API.
  • The application does not include telemetry, advertising SDKs, analytics SDKs or automatic crash-report uploads.
  • No online-AI API key is required.
  • Settings are stored in the user's local profile.
  • If diagnostic logging is enabled, diagnostic information may be written locally.

Development-time build scripts and user-initiated downloads from GitHub Releases can access the network. Those operations are separate from installed IME input processing.

Security policy

The latest Public Beta is currently the supported security-update target. We accept reports involving typed-content handling, elevation, MSI custom actions, named pipes, model verification and dependency integrity.

  • Use GitHub Private Vulnerability Reporting for sensitive reports when it is available.
  • Do not post secrets or sensitive reproduction data to a public Issue.
  • Release assets can be checked against the SHA256SUMS.txt published with the same release.
  • Certificates, API keys and private keys must not be committed to the repository.

Code-signing policy

The current Public Beta is unsigned. We do not represent unsigned binaries as signed. The project is preparing a verifiable code-signing path, including a SignPath Foundation application.

Future signatures are intended to cover Fumiori/Mozc-derived DLL, EXE and MSI artifacts produced from public source on GitHub-hosted Windows runners and traceable as GitHub Actions artifacts. Arbitrary local uploads and unrelated third-party binaries are outside the proposed signing boundary.

Intended provenance: public source/tag → GitHub Actions build → unsigned artifact → signing request → signed artifact → SHA-256 → GitHub Release.

Contributing

Issues, reproduction cases, documentation fixes, tests and code contributions are welcome. Reports in Japanese are also welcome.

  • Pull Requests should describe their purpose, user impact, test results and any licensing implications.
  • New network traffic, telemetry, persistent background work, elevated privileges or external datasets must be disclosed.
  • External code or data should record its source, revision, license and redistribution status.
  • Signing, release workflows, installer logic and dependency-fetching changes are treated as security-sensitive.
