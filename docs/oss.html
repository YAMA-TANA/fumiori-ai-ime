オープンソース

Yamatanaが独自に作成したコードは Apache License 2.0 で公開しています。ソースコード、ビルドスクリプト、GitHub Actionsのワークフロー、Mozcへの変更内容は公開リポジトリから確認できます。

Mozc、Ruri、ONNX Runtime、Qtなどの第三者コンポーネントは、YamatanaのApache-2.0へ置き換えられるのではなく、それぞれの上流ライセンスが適用されます。

プライバシーポリシー

IME入力、変換候補、前後文脈、辞書、文書分野、カスタム指示、AI推論は利用者のWindows PC内で処理します。

  • 入力内容や前後文脈を外部AI APIへ送信しません。
  • テレメトリ、広告SDK、解析SDK、クラッシュ自動送信を実装していません。
  • オンラインAIサービスのAPIキーは不要です。
  • 設定は利用者のローカルユーザー領域に保存されます。
  • 診断ログを有効にした場合、ローカルに情報が記録されることがあります。

開発時のビルドスクリプトや、利用者自身がGitHub Releasesからファイルを取得する操作ではネットワークを使用しますが、これはインストール後のIME入力処理とは別です。

セキュリティポリシー

現在は最新Public Betaをセキュリティ更新対象とします。入力内容、権限昇格、MSIカスタムアクション、Named Pipe、モデル・依存ファイル検証などに関する脆弱性報告を受け付けます。

  • 機密性のある脆弱性情報は、利用可能な場合GitHub Private Vulnerability Reportingを使用してください。
  • 公開Issueへ秘密情報や機微な再現データを投稿しないでください。
  • Release Assetsは同じReleaseで公開する SHA256SUMS.txt と照合できます。
  • 証明書、APIキー、秘密鍵はリポジトリへcommitしません。

コード署名ポリシー

現在のPublic Betaは未署名です。署名済みであるかのような表示は行いません。SignPath Foundationを含む、検証可能なコード署名経路の導入を準備しています。

将来の署名対象は、公開ソースからGitHub-hosted Windows runnerで生成され、GitHub Actionsの成果物として追跡できるYamatana/Mozc由来のDLL・EXE・MSIに限定する方針です。任意のローカルバイナリや無関係な第三者バイナリを署名対象にはしません。

想定する来歴: public source/tag → GitHub Actions build → unsigned artifact → signing request → signed artifact → SHA-256 → GitHub Release。

コントリビューション

Issue、再現手順、ドキュメント、テスト、コード変更を歓迎します。日本語での報告も受け付けます。

  • Pull Requestには目的、利用者への影響、試験結果、ライセンス上の追加事項を記載してください。
  • 新しいネットワーク通信、テレメトリ、常駐処理、権限追加、外部データを導入する場合は明示してください。
  • 外部コードやデータを追加する場合は出典・revision・ライセンス・配布可否を記録してください。
  • 署名、Release workflow、インストーラー、依存取得はセキュリティ上重要な変更として扱います。
